# Database rules (SQLite + Drizzle)

## Stack

- `expo-sqlite` (SDK-matched) + `drizzle-orm` 0.45.x + `drizzle-kit` 0.31.x with `dialect: 'sqlite'`, `driver: 'expo'`.
- Migrations are generated by `npx drizzle-kit generate` into `drizzle/`, bundled into the app (Metro `sourceExts` includes `sql`; `babel-plugin-inline-import` for `.sql`), and applied at startup **before** any route renders. A failed migration shows a blocking error screen — never continue with a half-migrated schema.
- Never use `drizzle-kit push` or `drop` against app data. Never edit an already-generated migration; add a new one.
- Enable `PRAGMA foreign_keys = ON` on every connection; use WAL journal mode.

## Schema conventions

- Tables (from the spec): `exercises`, `exercise_muscles`, `routines`, `routine_exercises`, `routine_sets`, `workout_sessions`, `session_exercises`, `workout_sets`, `app_settings`.
- Primary keys: `text` UUID v4. Foreign keys declared with explicit `onDelete` behavior.
- Timestamps: `integer` epoch ms (`created_at`, `updated_at`, `started_at`, `ended_at`, `completed_at`).
- Weight: `real` kilograms (`weight_kg`). Distances in meters, durations in seconds.
- `session_exercises` snapshots the exercise name and tracking type at session time; `exercise_id` is nullable with `ON DELETE SET NULL` so history survives exercise deletion. Sessions keep `routine_id` nullable with `ON DELETE SET NULL` and a routine-name snapshot.
- One active workout: enforce with a partial unique index on `workout_sessions(status) WHERE status = 'active'`, plus a service-level check.
- Analytics queries include only sets with `is_completed = 1` from sessions with `status = 'completed'`.
- `app_settings` is key/value; every value is parsed through its Zod schema with a default on read.

## Access rules

- Only `src/database/**` imports Drizzle or `expo-sqlite`. Repositories expose typed functions; services orchestrate.
- Any operation that writes more than one row (finish workout, save routine with sets, reorder, import) runs in a single `db.transaction`.
- Completing a set is one small write that commits immediately — do not batch it behind a debounce.
- Type repositories against the shared Drizzle SQLite base type so the same code runs on `expo-sqlite` in the app and an in-memory SQLite driver in Node tests.
- Validate rows crossing the boundary (imports, settings, restored sessions) with Zod.

## Schema change checklist

1. Edit `src/database/schema.ts` → 2. `npx drizzle-kit generate` → 3. review the SQL → 4. add/adjust repository tests including a migrate-from-previous test → 5. update `docs/DATABASE.md` → 6. run `architecture-reviewer`.
