# ATLAS contracts (v1)

Owner: Claude Code. Consumers: Codex's screens, through adapter hooks in `src/hooks/**`. Screens never import `src/database/**` or `src/services/**` directly.

Sources of truth (code):
- Domain schemas and types: `src/types/domain.ts`, `src/types/settings.ts`, `src/types/enums.ts`, `src/types/errors.ts` (import everything from `src/types`).
- Service interfaces: `src/services/contracts.ts`; injectable ports: `src/services/ports.ts`.
- Status: **v1 draft.** The types are tested (`tests/unit/types.*.test.ts`). The service interfaces have **no implementations yet**; each feature finalizes its section (EXL-05, RTN-04, WKT-06, HST-04, SET-01) and records the change in `HANDOFFS.md`. Do not build against a method that its feature task has not marked done.

## Conventions

| Topic | Contract |
|---|---|
| Weight | **Kilograms** (`weightKg`, `targetWeightKg`) everywhere in the domain. The kg/lb conversion is an adapter concern (SET-02): UI shows and parses the user's unit and calls the domain in kg. Changing the unit setting never changes stored data. |
| Time | Epoch milliseconds (UTC) as `number`. Durations from stored timestamps, never from a running JS timer. |
| Ids | UUID v4 strings, generated by the service (`IdGenerator`). |
| Distance / duration | metres / seconds |
| RPE | 1 to 10 in half-point steps (DEC-014); `null` = not recorded |
| Positions | Array order defines positions on write; reads return them sorted ascending, contiguous from 0 |
| Validation | Every service input is parsed with its Zod schema; failure rejects with `AtlasError('VALIDATION', ..., { issues })` |
| Errors | Services **reject with `AtlasError`** (`code`, `message`, `details?`). Raw SQLite errors never reach the UI: `message` and `details` are safe to show, the original error is only in `Error.cause` (logs). Adapters may use `attempt(fn)` to get `{ ok, value } | { ok: false, error }`; unexpected failures become `INTERNAL`. |
| Persistence promises | A write method's promise resolves only after the change is committed, and rejects if it failed. UI must show success only after resolution (matches Codex's `onCompleteSet` / `onFinish` semantics). |

### Error codes

| Code | Meaning | Typical UI response |
|---|---|---|
| `VALIDATION` | Input failed validation | Show field errors from `details.issues` |
| `NOT_FOUND` | Record does not exist | Navigate back / refresh |
| `ACTIVE_SESSION_EXISTS` | A workout is already active | Offer "Resume" |
| `NO_ACTIVE_SESSION` | Operation needs an active workout | Return to Home |
| `SESSION_NOT_ACTIVE` | Session already finished | Refresh |
| `EXERCISE_IN_USE` | A routine uses the exercise | Offer "Archive" |
| `HAS_HISTORY` | Sessions reference the exercise | Offer "Archive" |
| `SESSION_ACTIVE` | Tried to delete the active session | "Use Discard" |
| `PERSISTENCE` | Database failed (services translate repository errors) | Keep the draft, offer retry |
| `MIGRATION` | Startup migration failed | Blocking error screen |
| `INTERNAL` | Unexpected bug | Generic error; not retryable |

## Entities (read models)

| Type | Key fields | Invariants |
|---|---|---|
| `Exercise` | `id`, `builtinKey`, `name`, `equipment`, `trackingType`, `isCustom`, `isArchived`, `muscles[{muscle, role}]`, `notes` | Name 1-100 chars; muscle names lower-case; archived exercises are hidden unless `includeArchived` |
| `Routine` | `id`, `name`, `notes`, `exercises: RoutineExercise[]` | At most 50 exercises, 50 sets each |
| `RoutineExercise` | `id`, `exerciseId`, `exerciseName` (display join), `position`, `restSeconds`, `sets: RoutineSet[]` | |
| `RoutineSet` | `position`, `setType`, `targetReps`, `targetWeightKg`, `targetDurationSeconds`, `targetDistanceM` | Targets >= 0 or `null` |
| `WorkoutSession` | `id`, `routineId`, `name`, `status`, `startedAt`, `endedAt`, `restTimerEndsAt`, `exercises: SessionExercise[]` | At most one `active`; `endedAt` is `null` iff active |
| `SessionExercise` | `id`, `exerciseId` (nullable), `name`, `trackingType` (snapshots), `position`, `sets: WorkoutSet[]` | Snapshot never changes when the exercise or routine is edited or deleted |
| `WorkoutSet` | `target*` (planned, copied at start), `weightKg`, `reps`, `rpe`, `durationSeconds`, `distanceM`, `isCompleted`, `completedAt` | `isCompleted` and `completedAt` agree; only completed sets count in summaries and analytics |
| `WorkoutSummary` | `sessionId`, `name`, `startedAt`, `endedAt`, `durationMs`, `exerciseCount`, `completedSetCount`, `totalVolumeKg`, `records: PersonalRecord[]` (**draft**; always `[]` until ANL-03) | Volume = sum of `weightKg x reps` over completed weighted sets |
| `HistoryItem` / `HistoryPage` | `WorkoutSummary` + `routineId`; `{ items, nextCursor }` | Newest first; `nextCursor === null` at the end |
| `Settings` | `units` (kg/lb), `theme` (system/dark/light), `notificationsEnabled`, `defaultRestSeconds` (0-1800 s; 0 = no rest) | Missing or corrupt stored values fall back to defaults (`parseSettings`); defaults: kg, dark, true, 90 |

Write models (inputs): `ExerciseInput`, `ExerciseUpdate`, `ExerciseFilter`, `RoutineInput` (array order = positions, no ids), `StartWorkoutInput`, `SetValuesInput` (partial; `null` clears a value).

## Services (v1 draft signatures)

| Service | Methods | Errors |
|---|---|---|
| `ExerciseService` | `list(filter?)`, `get(id)`, `create(input)`, `update(id, patch)`, `archive(id)`, `unarchive(id)`, `remove(id)` | `VALIDATION`, `NOT_FOUND`, `EXERCISE_IN_USE`, `HAS_HISTORY` |
| `RoutineService` | `list()`, `get(id)`, `create(input)`, `update(id, input)`, `duplicate(id)`, `remove(id)` | `VALIDATION`, `NOT_FOUND` |
| `WorkoutService` | `getActive()`, `start(input?)`, `addExercise`, `removeExercise`, `addSet`, `updateSet`, `completeSet(setId, values?)`, `uncompleteSet`, `removeSet`, `setNotes`, `startRestTimer(seconds)`, `adjustRestTimer(deltaSeconds)`, `clearRestTimer`, `finish()`, `discard()` | `ACTIVE_SESSION_EXISTS`, `NO_ACTIVE_SESSION`, `NOT_FOUND`, `VALIDATION`, `PERSISTENCE` |
| `HistoryService` | `list(query?)` (`HistoryQuery`: limit 1-100, default 20), `get(sessionId)`, `getSummary(sessionId)`, `update(sessionId, patch)`, `updateSet(setId, values)`\*, `removeSet(setId)`\*, `remove(sessionId)` | `NOT_FOUND`, `SESSION_ACTIVE` (delete of the active session), `VALIDATION` |
| `SettingsService` | `get()`, `set(key, value)` | `VALIDATION` |

Behavioural guarantees (enforced and tested when implemented):
- `completeSet` is one immediate commit (no debouncing) and resolves only after it.
- `getActive()` returns the in-progress session after an app restart; tab switches never discard it.
- `finish()` is transactional and sets `endedAt = max(now, startedAt)`.
- `start()` copies routine names and targets into the session; later routine edits do not change it.
- Reordering uses the two-phase position update (DEC-013).

## Behaviour notes for adapters (from the architecture review)

- Every set mutation returns the whole `WorkoutSession`; the hook should update the tree so unchanged exercises and sets keep object identity (avoids re-rendering the session on every tap).
- Autosaved edits can race with completion: cancel or flush pending edits for a set before calling `completeSet(setId, values)`.
- `RoutineService.update` replaces all exercises/sets, so row ids change on every save; builder list keys must not use the ids of unsaved rows.
- `completeSet` on a set missing values required by its tracking type (for example `weight_reps` with no reps) is undefined in v1; it will be specified in WKT-02 before Codex relies on it.
- Weighted volume for `bodyweight_reps` is undecided (ANL-01/02).
- Rest timer adjustments are computed in the service from the stored end time, never in the UI.
- Domain read schemas trim/limit text; restore and import code must validate and normalize stored rows.

## Mapping from Codex's preview models (`src/features/preview/contracts.ts`)

These preview types are UI proposals, not contracts. The adapter hook (WKT-06) maps them:

| Preview | Domain | Adapter notes |
|---|---|---|
| `SetDraft.weight/reps/rpe` (strings) | `weightKg` / `reps` / `rpe` (numbers) | Parse and validate in the adapter; convert lb to kg using `Settings.units`; empty string = `null` |
| `SetDraft.completed` | `WorkoutSet.isCompleted` | Set only after `completeSet` resolves |
| `ExerciseDraft.previous` (text) | derived from the last completed session's sets | Adapter formats it; no stored field |
| `ExerciseDraft.equipment` | live join to `Exercise.equipment` | Not snapshotted; the adapter may show it only if the exercise still exists |
| `WorkoutModel.startedAt` (string) | `startedAt` (epoch ms) | Adapter formats; elapsed time derives from `startedAt` |
| `WorkoutActions.onCompleteSet` | `WorkoutService.completeSet` | Resolve-after-commit, reject on failure |
| `WorkoutActions.onFinish` | `WorkoutService.finish` | Transactional |
| `WorkoutActions.onEditSet` / `onNotesChange` | `updateSet` / `setNotes` | Autosave policy: write on blur or after a short idle; failures surface to the UI |

## Change process

1. Change the schema/interface in `src/types` or `src/services/contracts.ts`; update this file.
2. Add or update tests; run `npx tsc --noEmit`, `npm run lint`, `npm test -- --runInBand`.
3. Append a dated entry to `docs/HANDOFFS.md` describing what Codex can now consume or must change.
