# ATLAS database

Owner: Claude Code. Source of truth: `src/database/schema.ts`; generated migration `drizzle/0000_init.sql` (never edit a generated migration; add a new one). Rules: `.claude/rules/database.md`.

## Conventions

| Topic | Rule |
|---|---|
| Keys | UUID v4 text, generated by the app |
| Time | integer epoch milliseconds (UTC) |
| Weight | kilograms, `REAL` (`*_kg`); converted only at the display/input edge |
| Booleans | integer 0/1 |
| Engine settings | `PRAGMA foreign_keys = ON` on every connection (set at connection time in FND-11) |
| Enums | stored as text and guarded by `CHECK` constraints |

## Tables

| Table | Purpose | Key constraints |
|---|---|---|
| `exercises` | Built-in and custom exercises | unique `builtin_key` (NULL for custom) for idempotent seeding; `tracking_type` in (weight_reps, bodyweight_reps, duration, distance_duration); non-blank name; `is_archived` instead of deletion |
| `exercise_muscles` | Muscle links | PK (exercise_id, muscle); role primary/secondary; cascade on exercise delete |
| `routines` | Workout templates | non-blank name |
| `routine_exercises` | Ordered exercises in a routine | unique (routine_id, position); exercise FK `RESTRICT` (archive instead); cascade from routine |
| `routine_sets` | Planned sets | unique (routine_exercise_id, position); targets (reps, kg, seconds, metres) >= 0 |
| `workout_sessions` | Active and completed workouts | **partial unique index: at most one row with status `active`**; `ended_at` null iff active, and >= `started_at` when completed; `routine_id` set null on routine delete; `rest_timer_ends_at` persists the rest countdown |
| `session_exercises` | Historical exercise snapshots | `name` and `tracking_type` copied at session time; `exercise_id` set null on exercise delete; cascade from session |
| `workout_sets` | Actual performance plus copied planned `target_*` | RPE 1-10; values >= 0; `is_completed` and `completed_at` must agree (both set or both unset); cascade from session exercise |
| `app_settings` | Key/value preferences | `value` is JSON, parsed through Zod with defaults on read |

## Invariants enforced by the database

- One active workout; a completed session always has an end time.
- History independence: deleting a routine or an exercise never alters completed sessions (verified below).
- No orphan rows: foreign keys on, cascades only downward within a session or routine.
- Analytics read only `is_completed = 1` sets of `completed` sessions (a service-level rule; analytics reach sets through `session_exercise_id`).

## Policies (DEC-013)

FK-safe migrations (FKs off around `migrate()` + `foreign_key_check`), two-phase reorder, clamped finish time, live muscle attribution. See `docs/DECISIONS.md` DEC-013.

## Notes for service authors

- `position` columns have unique indexes. Reordering must not collide mid-update: use a two-step shift (move to a temporary offset, then to final positions) inside one transaction.
- Multi-row writes (finish workout, save routine, reorder, import) run in a single `db.transaction`.
- Completing a set is one small write that commits immediately.
