### DEC-001 · Ordered milestones, no sprints
- **Context:** ATLAS has one human developer supported by two AI agents. Sprint ceremonies, story points and fixed deadlines add overhead with no team to coordinate.
- **Decision:** Track work as ten ordered milestones split into small, verifiable tasks (`docs/FEATURE_TRACKER.md`). No sprints, story points or artificial deadlines.
- **Consequences:** The order comes from task dependencies, not dates. PRODUCT_SPEC §10's sprint table is historical; the ten tracker milestones replace it.

### DEC-002 · The Markdown tracker is the single source of truth
- **Context:** Two agents update status, often in the same working tree. Hand-calculated percentages drift, and partial work tends to get counted as complete.
- **Decision:**
  - `docs/FEATURE_TRACKER.md` is the only task system.
  - Progress = Done tasks ÷ all tracked tasks, overall and per milestone.
  - The progress figures in `docs/PROJECT_STATUS.md` are generated by `node scripts/tracker.mjs --write`.
  - The validator enforces the rules: Done needs evidence and Done dependencies; Ready needs Done dependencies; Blocked must name its blocker; IDs are unique; no dependency cycles.
- **Consequences:**
  - One row per task keeps concurrent edits and Git merges line-local.
  - Adding tasks lowers the percentage; that's intended, since it reflects real scope.
  - Infrastructure tasks (FND-01, FND-02, FND-04) count toward overall progress. Status reports also state app-feature completion separately.

### DEC-003 · Agent ownership split
- **Context:** Spec §2 assigns architecture, persistence, logic, integration and builds to Claude Code, and UI/UX to Codex. Both agents work concurrently.
- **Decision:**
  - The ownership map lives in `.claude/rules/collaboration.md`, mirrored in `AGENTS.md`.
  - Claude Code's PreToolUse hook asks before editing Codex-owned paths or overwriting an existing shared file.
  - Shared docs are merged and append-only.
- **Consequences:** Cross-agent requests go through `docs/HANDOFFS.md` and the user. Each agent changes the status of its own tasks only.

### DEC-004 · Expo SDK 58 with development builds (Proposed)
- **Context:** On 2026-11-09, SDK 58 is the latest stable release (React Native 0.88.1, React 19.3, Reanimated 4.7.1, `expo-sqlite` ~58). ATLAS is installed privately, not distributed through a store.
- **Decision:** Target SDK 58. Install Expo packages with `npx expo install`. Use `expo-dev-client` builds, not Expo Go. Native folders are generated (Continuous Native Generation) and git-ignored.
- **Consequences:** On-device testing needs a development build, either local (JDK 17 and Android SDK) or EAS (Expo account). To be confirmed when FND-06 runs.

### DEC-005 · NativeWind 4.2 with Tailwind CSS 3.4 (Proposed)
- **Context:** The spec requires NativeWind. NativeWind 5 is still a release candidate, and NativeWind 4 doesn't support Tailwind 4.
- **Decision:** Use NativeWind 4.2.x with Tailwind CSS 3.4. The Tailwind config imports Codex's `src/theme` token values and never duplicates them.
- **Consequences:** Compatibility with React Native 0.88 is unproven until FND-08. If it fails, stop and present options rather than switch silently.

### DEC-006 · Data conventions (Proposed)
- **Context:** Spec §6 requires UUID keys, foreign keys, migrations, transactions, kilograms as the stored unit, history independent of routine edits, one active workout, and analytics that ignore incomplete sets.
- **Decision:**
  - UUID v4 text keys.
  - `weight_kg` stored as REAL.
  - Timestamps as integer epoch milliseconds (UTC).
  - `session_exercises` keeps snapshots, with a nullable `exercise_id` that is set to null on delete.
  - A partial unique index on `workout_sessions(status) WHERE status = 'active'`.
  - Settings stored as Zod-validated key/value pairs.
- **Consequences:** Spec-mandated parts are fixed. Storing timestamps as epoch milliseconds is confirmed at FND-10.

### DEC-007 · Shared skills point to Codex's pinned copies
- **Context:** Codex had already copied the Callstack `react-native-best-practices` and `react-native-testing` skills into `.agents/skills`, pinned at commit `59e9d174`. Installing the plugin versions doesn't work on this machine because they rely on git symlinks.
- **Decision:** `.claude/skills/*` contain pointer skills that read Codex's copies. There is no second copy.
- **Consequences:** If Codex moves or re-pins those folders, it notes that in HANDOFFS so the pointers get updated.

### DEC-008 · Global TypeScript pinned to major 6
- **Context:** TypeScript 7 (the native port) no longer ships the `tsserver` that `typescript-language-server` needs. The SDK 58 template uses `typescript ~6.0.3`.
- **Decision:** `npm i -g typescript@6` alongside `typescript-language-server` 6.0.3.
- **Consequences:** The project's own local TypeScript takes precedence once the app is scaffolded. Revisit when the language server supports TypeScript 7.

### DEC-009 · Use the `gh` CLI; no GitHub MCP server
- **Context:** `gh` is already signed in. The GitHub MCP server would need a personal access token stored in the environment.
- **Decision:** Use `gh`. Commits, pushes, merges and repo or PR creation always ask the user first (`.claude/settings.json`).
- **Consequences:** None beyond tooling. Pushes always need the user's explicit approval (see AGENTS.md).

### DEC-010 · GitHub Projects as an optional one-way mirror (Proposed)
- **Context:** The user asked for a proposed board if GitHub Projects is available. On 2026-11-09 it isn't: the `gh` token lacks the `project` / `read:project` scopes, and no GitHub repo exists yet (FND-05).
- **Proposal:** A Projects (v2) board with the columns **Backlog → Ready → In Progress → In Review → Done**:
  - One item per task, with the title `<ID> <Task>`.
  - Custom fields: `Task ID`, `Milestone`, `Owner`, `Blocked` (yes/no) and `Blocker`.
  - **Blocked** tasks sit in **Backlog** with a `blocked` label and the blocker text, because the board has no Blocked column.
- **Synchronization:**
  - The Markdown tracker stays the source of truth; the board is a **read-only mirror**.
  - A future `node scripts/tracker.mjs --sync-github` (or a GitHub Action on pushes to `main`) creates or updates items keyed by `Task ID` using `gh project item-create/item-edit`.
  - Moving a card on the board changes nothing. To change status, edit the tracker row and commit; the next sync moves the card.
  - The sync reports any card whose board status differs from the Markdown, so drift is visible rather than silently overwritten.
- **Prerequisites (user approval each):**
  - FND-05: repo and push.
  - `gh auth refresh -s project`.
  - Creating the project.
  - Then a tracker task to build and verify the sync.
- **Consequences:** Without the sync, no board is created, so there's never a second, unsynchronized task system.
